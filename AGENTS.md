# AGENTS.md

Личный Telegram-бот расписания группы А-11 БТЭУ (Гомель). Один пользователь — владелец
(фильтр по `MY_TELEGRAM_ID`), всем остальным бот молчит. Крутится 24/7 на бесплатном
fps.ms с жёстким лимитом **128 МБ RAM**. Всё пользовательское общение — по-русски,
сдержанный стиль, без эмодзи. Контракт поведения — `SPEC.md`; данные расписания —
`schedule_data.py`.

## Критические ограничения (не нарушать)

- **Только aiohttp.** Никаких aiogram, pyTelegramBotAPI и прочих фреймворков: импорт
  aiogram 3 не помещается в 128 МБ (подтверждено замером: зависает на 127.9 МБ).
  Транспорт — самописный класс `Telegram` на aiohttp + long polling.
- **Любая новая зависимость** требует: (1) обстоятельной причины, (2) wheel-файла
  cp311 manylinux, положенного в `wheels/` — сетевой `pip install` на хостинге убивается
  OOM, ставится только `pip install --no-index --find-links wheels`, (3) замера памяти
  до и после локально.
- **Только polling, никаких webhooks** — не поддерживается спекой и хостингом.
- **Часовой пояс фиксированный UTC+3**: `timezone(timedelta(hours=3))`. pytz/zoneinfo
  не подключать.
- **Никаких эмодзи** в текстах бота (сообщения, кнопки, календарь, .ics-названия).
  Форматирование — Telegram HTML (`<b>`, `<i>`, `<code>`, `<blockquote>`), parse_mode
  = "HTML".
- **Каждая динамическая строка, попавшая в HTML, — через `html.escape`** (предметы,
  преподаватели, аудитории, суффиксы).
- Бот отвечает **только владельцу**: не ослаблять фильтр `OWNER_ID` и не добавлять
  публичные команды.
- `.env` и любые токены в репо не попадают никогда. Секреты живут в `.env` (локально)
  и GitHub secrets (`BOT_TOKEN`, `MY_TELEGRAM_ID`, `FPSMS_API_KEY`).

## Владение файлами

- **`schedule_data.py` — единственный источник данных расписания.** Предметы, время,
  аудитории, преподаватели, чередование недель, звонки, типы занятий (KIND), границы
  семестра живут только там. В `bot.py` ничего про расписание не хардкодить — bot.py
  только рендерит и раздаёт.
- **`SPEC.md` — контракт внешнего поведения.** Любое изменение текстов, форматов
  сообщений, кнопок или логики ответов сопровождается правкой соответствующего пункта
  SPEC.md в том же коммите. Не менять формат сообщений «просто так» — сначала SPEC.
- **`wheels/`** — только скачанные с PyPI wheel-файлы; руками их не править.
- **`run.py`** — бутстрап на сервере (git pull + pip из wheels + exec bot.py); менять
  только вместе с проверкой, что старт ещё влезает в лимит памяти.

## Команды

```bash
# локальный запуск (нужен .env с BOT_TOKEN и MY_TELEGRAM_ID)
python -X utf8 bot.py

# проверка логики без сети: якорь чередования недель
python -c "from datetime import date; import schedule_data as sd; \
assert sd.week_mark(date(2026,9,21))=='под' and sd.week_mark(date(2026,10,26))=='над'"

# задеплоить: push в main -> GitHub Actions перезапускает сервер (даунтайм 30–40 с)
git push origin main

# проверить, что прод-бот жив (ОБЯЗАТЕЛЬНО timeout>=5; timeout=0/1 врёт — вернёт OK)
curl -s --max-time 30 "https://api.telegram.org/bot\$BOT_TOKEN/getUpdates?timeout=25" | grep -c 409
```

Важно: локальный `bot.py` с прод-токеном конфликтует по 409 с сервером на fps.ms.
Для локального теста с сообщениями — остановить прод через панель или взять тестовый
токен от отдельного бота.

## Инфраструктура fps.ms

- Сервер `a11-schedule-bot`, панель `panel.fps.ms/server/1438731f`, полный UUID в
  `.env` (`FPSMS_SERVER_UUID`).
- **Продление «Add 24 hours» — только вручную** (рекапча, автоматизации нет; без
  продлений 28 дней подряд сервер удалят). Watchdog внутри bot.py напоминает в
  Telegram при остатке <30 ч и <6 ч — не удалять.
- Startup-переменные панели менять только **PUT**
  `/api/client/servers/{uuid}/startup/variable` (PATCH даёт 405). Рестарт — POST
  `/power` `{"signal":"restart"}`.
- Запросы к панели из Python-скриптов: Cloudflare режет сигнатуру urllib — нужен
  браузерный User-Agent или curl. Консоли по HTTP нет: живой лог — websocket
  (`GET /api/client/servers/{uuid}/websocket` → auth → события `console output`).
- Автодеплой: `.github/workflows/deploy.yml` (push → рестарт, сервер сам делает
  git pull по AUTO_UPDATE=1). Healthcheck: `.github/workflows/healthcheck.yml`,
  ежечасно, тревога владельцу + рестарт при отсутствии 409 (там timeout=5 —
  корректный, не менять на 0).

## Процедура смены семестра (редкая, делать строго по шагам)

1. Открыть bteu.by → «Студенту» → «Расписание занятий» → «Формирование учебных
   недель» и взять официальную таблицу (над/под чертой по датам). Сайт публикует
   её не сразу — до публикации старую не менять.
2. Определить `ANCHOR_MONDAY` (понедельник любой недели с известной чертой; сейчас
   21.09.2026 = «под») и вписать `SEMESTER_START`/`SEMESTER_END`.
3. Скачать стабильное расписание факультета (страница «Стабильное расписание»
   факультета, .xls по группе) и переписать `SCHEDULE`. Формат записи — 7-кортеж,
   описан в шапке schedule_data.py; варианты недель помечаются «над»/«под»/«both».
4. Обновить `KIND` при появлении новых предметов. Типы сайт не публикует: источник —
   скриншоты оригинального бота @bteusupbot + структура файла (две аудитории/два
   преподавателя = подгруппы = практика; «1-2» обе подгруппы вместе = лекция).
5. Проверить `week_mark` якорными датами из официальной таблицы (см. команду выше).
6. Обновить SPEC.md одним коммитом со всеми правками.

## Стиль кода

- Комментарии, докстринги и тексты бота — по-русски; стиль и плотность комментариев —
  как в существующих файлах, без лишнего пересказа очевидного.
- Строки данных (аудитории «3-27,3-30», преподаватели «доц. Кузьменкова И.А.»)
  переносить из источника дословно; должности (доц., ст.пр., пр., пр.-ст.) — часть
  строки преподавателя.
- Фамилии преподавателей сверять с сайтом кафедры при сомнении — в файле расписания
  бывают опечатки (пример: «Кузменкова» в xls vs правильное «Кузьменкова»).
- Рендер вычислять в чистых функциях (текст сообщения отдельно от отправки) — так
  проще тестировать без сети.
- Python 3.11, стандартная библиотека + aiohttp + python-dotenv. Без новых
  инфраструктурных зависимостей.

## Перед коммитом

- Прогнать якорную проверку `week_mark` (команда выше) и хотя бы один вызов
  `day_text`/`week_text` для даты сегодня.
- Убедиться, что `git status` не содержит `.env`, `__pycache__`, временных файлов.
- Если менялось внешнее поведение — SPEC.md обновлён в этом же коммите.
- Push в main = автодеплой; после пуша проверить живость прод-бота (409-тест с
  timeout>=5).
