# Спецификация личного бота расписания группы А-11 (БТЭУ)

Артефакты: SPEC.md (этот файл) и schedule_data.py (единственный источник данных).
Код бота в эту спецификацию не входит.

## 1. Назначение и рамки

1. Бот для одного человека. Токен и MY_TELEGRAM_ID берутся из переменных окружения.
2. Сообщения от MY_TELEGRAM_ID обрабатываются; от всех остальных — полное молчание: без ответа, без реакции.
3. Только long polling. Без webhook, веб-сервера, базы данных и файлов состояния. Один процесс.
4. Часовой пояс — фиксированный UTC+3 (Минск), одной константой `timezone(timedelta(hours=3))`. pytz/zoneinfo не используются, чтобы не зависеть от tz-базы хостинга.
5. Приветствие /start: «Расписание группы А-11. Выбирай кнопками ниже.» Источник правды по расписанию — schedule_data.py: `SCHEDULE`, `week_mark`, `SEMESTER_START`, `SEMESTER_END`, `BELLS`. Данные в коде бота не дублируются.

## 2. Команды и клавиатура

6. Единственная команда — /start: однострочное приветствие + reply-клавиатура. Других команд нет, никакого текста /start не возвращает, кроме одной строки.
7. Reply-клавиатура, два ряда: «Сегодня» «Завтра» «Сейчас» «Неделя» / «Звонки» «Выбрать день». Тексты кнопок без эмодзи.
8. Любой другой текст от владельца игнорируется молча (без сообщений об ошибке).

## 3. Просмотр одного дня

Кнопки «Сегодня», «Завтра» и тап по дате в календаре отправляют расписание одного дня.

9. Шаблон сообщения:

```
Пятница, 23.10.2026 · сегодня
Неделя под чертой
▰▰▰▰▱▱▱▱▱▱
пары 09:00–16:15

1-я пара 09:00–10:35
Лекция · Экономическая теория, ауд. 2-11
ст.пр. Барабанова И.В.

2-я пара 10:50–12:25
...
```

10. Первая строка: день недели с заглавной буквы и дата DD.MM.YYYY. Суффикс « · сегодня» добавляется только при показе по кнопке «Сегодня», « · завтра» — только по кнопке «Завтра»; даты, выбранные в календаре, выводятся без суффикса — даже если это сегодня или завтра.
11. Вторая строка: «Неделя над чертой» либо «Неделя под чертой».
12. Блок пары — три строки, разделённые пустой строкой от соседних блоков:
    - «N-я пара HH:MM–HH:MM»;
    - «Предмет» или «Предмет, ауд. комнаты» (аудитории — строка из данных как есть, без аудитории запятая не пишется);
    - преподаватели через запятую, одной строкой.
13. День без пар: две строки заголовка, пустая строка, строка «пар нет».
14. После строки черты, если в дне есть пары: диапазон дня «пары HH:MM–HH:MM» (от первой до последней пары); для сегодняшнего дня — моношрифт-блок с прогресс-баром из 10 клеток (▰ пройдено, ▱ осталось) над диапазоном.
15. Статус дня вычисляется в момент отправки по UTC+3, выводится для сегодняшнего дня:
    - до 1-й пары, в промежутке между парами и после последней пары — курсивная строка под баром: «до первой пары N мин», «перемена, до N-й пары M мин» (N — номер следующей пары; любой промежуток между соседними парами дня — «перемена», независимо от длительности), «занятия окончены»;
    - идёт пара — статусной строки нет, вместо неё внутри блока идущей пары курсивная заметка «до конца M мин»;
    - пар нет: «сегодня пар нет» (заменяет собой строку «пар нет» из п. 13).
    Интервалы: «N мин», от 60 минут — «N ч M мин», при ровном числе часов — «N ч» (60 минут — «1 ч»). Момент окончания пары — уже перемена/окончание; момент начала — уже пара.
16. Тип занятия («Лекция»/«Практика») выводится перед предметом через « · » в видах дня, «Сейчас», «Неделя» и утренней сводке (у предметов без типа — не выводится). Типы задаются словарём KIND в schedule_data.py и не дублируются в bot.py. Источник типов: скриншоты оригинального бота + структура официального стабильного расписания (две аудитории/два преподавателя = подгруппы = практика; «1-2» обе подгруппы вместе = лекция); сам сайт bteu.by типов не публикует.

## 4. Кнопки «Сейчас» и «Неделя»

17. «Сейчас» показывает состояние на момент отправки: шапка «Сейчас HH:MM · День, DD.MM» + черта недели + бар и диапазон дня (кроме «занятия окончены»); идущая пара — блок с «до конца N мин» и цитатой «дальше: N-я пара в HH:MM — Предмет, ауд.» (если есть следующая); переменa/до первой — курсивная строка и блок следующей пары; «занятия окончены»/«сегодня пар нет» — с цитатой «завтра: …»/«ближайшая пара: …» (с аудиторией) в пределах недели вперёд.
18. «Неделя» показывает неделю, содержащую сегодня; под сообщением — inline-кнопки «‹»/«›» (предыдущая/следующая неделя с сохранением формата) и «экспорт в календарь».
19. Шаблон недели (пример для реальной под-чёрной недели):

```
Неделя 19.10–25.10 · под чертой

Пн 19.10
1 (09:00) Физическая культура
2 (10:50) Математический анализ, ауд. 1-13
3 (12:55) Компьютерные информационные технологии, ауд. 1-2
4 (14:40) Информационный час, ауд. 3-27
4 пары

Сб 24.10
1 (09:00) Линейная алгебра и аналитическая геометрия, ауд. 1-9
2 (10:50) Линейная алгебра и аналитическая геометрия, ауд. 1-9
2 пары

Вс 25.10
пар нет
```

20. Блок дня: строка «Пн DD.MM», далее одна строка на пару: «N (HH:MM) Предмет» с «, ауд. комнаты» при наличии. У сегодняшнего дня к строке добавляется « · сегодня» (жирным вместе с датой). Если суббота и воскресенье пусты, они выводятся одним блоком «Сб–Вс DD.MM · DD.MM»; пометка « · сегодня» ставится, если сегодняшний день входит в этот блок. Преподаватели в недельном виде не выводятся.
21. Итоговая строка дня: «1 пара», «2 пары», «3 пары», «4 пары», «5 пар» (1 — пара; 2–4 — пары; 5 и больше — пар). День без пар — «пар нет» курсивом. Если пар нет всю неделю (каникулы), вместо блоков дней — одна строка «пар нет» курсивом. Блоки дней разделяются пустой строкой.
22. Кнопка «экспорт в календарь» отправляет .ics-файл выбранной недели: событие на каждую пару (предмет — SUMMARY, аудитория — LOCATION, преподаватели — DESCRIPTION), время локальное плавающее, имя вида «raspisanie_26.10-01.11.ics», подпись с чертой недели.

## 5. Кнопка «Звонки»

23. Отправляет таблицу звонков в HTML: заголовок «Расписание звонков» жирным, ниже — моношрифт-дерево: на каждую пару четыре строки — «N-я  HH:MM–HH:MM   перерыв N мин» (у последней пары перерыва нет), «├ 1-й час  HH:MM–HH:MM», «├ перемена 5 мин» (вычисляется из BELLS), «└ 2-й час  HH:MM–HH:MM». Все данные берутся из структуры `BELLS` в schedule_data.py.

## 6. Кнопка «Выбрать день» (inline-календарь)

24. По нажатию приходит жирная строка «Выбери день» и inline-клавиатура: первая строка «‹» «Название месяца год» «›» (например «‹ Октябрь 2026 ›»), вторая — строка заголовков дней недели «Пн Вт Ср Чт Пт Сб Вс» (неактивные кнопки), ниже — сетка дат текущего месяца, недели начинаются с понедельника. Кнопка сегодняшней даты помечается точкой после числа («23·»).
25. «‹» и «›» переключают месяц. Стрелка не выводится, если соседний месяц не пересекается с семестром.
26. Кнопки-даты активны только в пределах SEMESTER_START..SEMESTER_END; дни вне семестра — пустые (неактивные) клетки.
27. Тап по дате отправляет новое сообщение с расписанием этого дня по разделу 3 (без суффикса « · сегодня/завтра»); сообщение с календарём не редактируется и остаётся в чате.

## 7. Недели над/под чертой

28. Чередование по неделям (Пн–Вс). Якорь: неделя с понедельника 21.09.2026 — ПОД чертой. Подтверждение по исходной таблице: все варианты «под чертой» имеют пометки «с 21.09.26 / 24.09.26 / 25.09.26 / 26.09.26», и все эти даты лежат в одной неделе 21–27.09.2026.
29. Расчёт — функцией `week_mark(day)` из schedule_data.py. Даты до якоря экстраполируются тем же правилом (чередование продолжается в обе стороны).
30. Даты вне SEMESTER_START..SEMESTER_END — каникулы: любой день «пар нет». Кнопки «Сегодня»/«Завтра» за пределами семестра тоже дают «пар нет».

## 8. Стиль

31. Сообщения без эмодзи. Форматирование — Telegram HTML (parse_mode="HTML"): в виде дня шапка, номера пар и заметка «до конца» жирным/курсивом, статусные строки курсивом; «Звонки» — моношрифт-дерево; «Неделя» — жирные шапка и дни, счётчики курсивом; подсказки «дальше/завтра/ближайшая» — цитатой-блоком. Никаких markdown-символов в самом тексте сообщений.
32. Отступы и разделители — строго по шаблонам разделов 3–5; экранирование HTML обязательно (html.escape для предметов, имён, суффиксов).
33. Названия предметов, аудитории и преподаватели выводятся дословно из schedule_data.py, без сокращений и перестановок; перечни аудиторий выводятся с пробелом после запятой («3-36, 3-24»).

## 9. Надёжность и инфраструктура

34. Деплой: пуш в main ветку репозитория запускает GitHub Actions (deploy.yml), который через API панели fps.ms перезапускает сервер; при старте сервер сам делает git pull (AUTO_UPDATE) и запускает run.py (клон при пустой папке, установка зависимостей офлайн из wheels/).
35. Healthcheck: GitHub Actions ежечасно проверяет, что бот держит polling (пробный getUpdates должен вернуть 409); при сбое бот-уведомление владельцу и попытка рестарта через API панели (healthcheck.yml).
36. Watchdog продления: bot.py раз в час читает срок сервера через API панели и отправляет владельцу «Напоминание: сервер fps.ms остановится примерно через N ч. Продли сервер в панели (кнопка Add 24 hours): URL панели», когда до остановки остаётся 30 часов и затем 6 часов; в тексте — фактический остаток в часах (продление защищено reCAPTCHA и не автоматизируется честно). Состояние в памяти: рестарт бота в том же статусе даёт повторное напоминание.
37. Утренняя сводка: ежедневно в MORNING_SUMMARY_TIME (по умолчанию 07:30 по Минску, задаётся в .env; пустое значение выключает) бот сам присылает раскладку дня: шапка «Доброе утро · День, DD.MM.YYYY» + черта недели + моношрифт-бар с диапазоном дня, ниже через пустую строку — «до первой пары N мин» (если сводка пришла до начала 1-й пары), по строке «N (HH:MM) Предмет, ауд.» на пару, итог «N пар(ы)»; в дни без пар — «сегодня пар нет». Сводка не отправляется вне SEMESTER_START..SEMESTER_END и не догоняется, если бот был выключен в окно отправки (90 минут); состояние в памяти — рестарт бота в окне может отправить сводку за день повторно.
