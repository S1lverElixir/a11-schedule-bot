# Бот А-11 на Rust

Здесь весь код бота, и он же работает в проде. Прежняя Python-реализация удалена;
её поведение осталось в `tests/fixtures` — на него сверяется каждая сборка.

## Что где

- `src/date.rs` — календарь и часы. Дат и времени в нём больше, чем кажется: дни от
  1970-01-01, день недели, UTC+3 без tz-базы, разбор ISO для срока сервера.
- `src/schedule.rs` — расписание, датные замены, звонки, типы занятий, границы
  семестра, якорь недель. Единственный источник правды; в комментарии файла записано,
  чем сверена каждая строка.
- `src/render.rs` — все тексты: день, «Сейчас», неделя, календарь, звонки, сводка.
  Чистые функции, сети не касаются, поэтому их и проверяет паритет.
- `src/ics.rs` — `.ics` по RFC 5545: CRLF, фолдинг по 75 октетов, экранирование.
- `src/telegram.rs` — Bot API по HTTP/1.1: JSON-вызовы и одна multipart-отправка файла.
- `src/bot.rs` — обработчики кнопок, утренняя сводка, сторож продления.
- `src/main.rs` — конфигурация, очистка webhook, поток опроса с растущей паузой при
  бое сети и флаги `--version`, `--selftest`, `--check-net`, `--dump-views`, `--dump-schedule`.
- `src/snapshot.rs` — перечисление и вычисление всех снимков видов: тем же кодом
  бинарник пересобирает эталон (`--dump-views`) и его сверяет паритет-тест.
- `src/log.rs` — логи, в которых токен заменяется звёздочками.

Зависимости две: `ureq` (HTTP + TLS на rustls, корневые сертификаты внутри бинарника)
и `serde_json`. Ни async-рантайма, ни chrono: при одном пользователе дешевле три
обычных потока — опрос, сводка и сторож — и своя арифметика дат.

## Проверки

```powershell
python -X utf8 rust/tools/check.py   # сборка, тесты, паритет, память
cd rust; cargo test                  # то же без Python-обвязки
```

Паритет: `rust/tests/fixtures/views.json` — 7600 снимков текстов (день, «Сейчас»,
неделя, календарь, звонки, `.ics`, утренняя сводка) за 2026-05-01…2027-04-30 при
замороженных часах. `cargo test` пересчитывает каждый случай Rust-кодом и сравнивает
байт-в-байт.

`rust/tests/fixtures/handlers.json` — 70 снимков обработчиков: какие вызовы Bot API
делает бот на каждое сообщение и нажатие (текст, клавиатура, `parse_mode`, имя и
содержимое `.ics`, фильтр владельца, кривой `callback_data`). `tests/handlers.rs` подменяет
сеть записывающей заглушкой и сверяет вызовы с эталоном.

Снимки — эталон, а не производная: Python-бота, который их создавал, в репозитории
больше нет. Поэтому паритет отвечает на вопрос «Rust не изменил поведение», а не
«Rust прав». Видовые снимки умеет пересобирать сам бинарник:
`a11-bot --dump-views rust/tests/fixtures/views.json`, после чего читают diff и
коммитят его только если изменение и было целью. Снимки обработчиков пересобрать
нечем — они заморожены как есть, и правка вызова Bot API означает правку файла
вручную с полным diff перед глазами. При смене семестра — тот же порядок: данные,
снимки и SPEC одним коммитом.

## Память

- пик при построении всех видов за семестр (включая TLS-клиент): 5,3–5,4 МБ;
- живой контейнер в покое: 11–14 МБ;
 - при недоступном Telegram опрос отступает на 3, 6, 12, 25 секунд: в худшем случае
  144 попытки в час вместо 1200, которые давала фиксированная пауза в три секунды;
- лимит хостинга — 128 МБ.

Замер: `a11-bot --selftest 2` печатает объём, хеш всех видов и пик памяти процесса.
Хеш детерминированный, поэтому сравним между машинами.

## Запуск

Переменные окружения: `BOT_TOKEN`, `MY_TELEGRAM_ID`,
`MORNING_SUMMARY_TIME`, `FPSMS_API_KEY`, `FPSMS_SERVER_UUID`, `FPSMS_PANEL_URL`.
Если переменных нет, читается `.env` рядом с рабочим каталогом.

```powershell
cargo build --release --manifest-path rust/Cargo.toml
rust\target\release\a11-bot.exe --selftest 2      # память и хеш видов, сети нет
rust\target\release\a11-bot.exe --check-net       # getMe: принят ли токен
```

Оба режима ничего не пишут в чат. Запуск самого бота (`a11-bot.exe` без флагов) под
настоящим токеном поднимает второй polling-процесс: прод при этом получает конфликт
409, а сообщения владельца может обработать локальная копия — и не обработает прод.
Локально без флагов бота запускают только на тест-токене.

`--dump-schedule` отдаёт данные JSON — этим их сверяет `tools/check_site.py`.

## Сборка под хостинг

Хостинг — Linux x86_64, поэтому нужен статический бинарник:

```powershell
rustup target add x86_64-unknown-linux-musl
cargo build --release --target x86_64-unknown-linux-musl   # нужен musl-gcc; на Windows проще через CI
```

`.github/workflows/rust.yml` собирает такой бинарник на каждый пуш в `main`, который
трогает `rust/`, прогоняет тесты и `--selftest` на Linux, кладёт бинарник в артефакты,
в скользящий релиз `rust-latest` и коммитит его как `rust/bin/a11-bot`. Если файл
изменился, workflow сам просит панель перезапустить сервер: контейнер подтянет новый
бинарник. Скачать на другом хосте: `rust/tools/fetch.sh` (для приватного репозитория
нужен `ACCESS_TOKEN`).

## Как это работает в проде

1. Панель fps.ms запускает `run.py` (переменная старта `PY_FILE=run.py`).
2. `run.py` копирует `rust/bin/a11-bot` во временный каталог, ставит право запуска и
   гоняет `--selftest 1`. Не прошёл — `run.py` выходит с причиной в консоли панели.
3. Бинарник заменяет процесс собой, поэтому Python в памяти не остаётся.

Отката на другой язык больше нет: если бинарник не проходит самотест, бот молчит,
и чинить надо коммитом (или `git revert`). Файл в репозитории нельзя `chmod`-ить:
смена режима ломает автообновление (`git pull` падает на локальном изменении).

## Не проверено

- Живой обмен с чатом сверяется руками: код и параметры вызовов подтверждены снимками,
  но что пришло в Telegram — видит только владелец.
 - Сторож продления в проде срабатывал: напоминание приходило владельцу в чат.
  Утренняя сводка в окне 07:30 не проверялась; обе отправки вне снимков, потому что
  это не вызовы обработчиков.
- Растущая пауза опроса проверена тестом функции, но не настоящим обрывом сети.
