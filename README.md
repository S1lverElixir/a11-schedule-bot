# Расписание А-11 (БТЭУ)

Личный Telegram-бот расписания учебной группы. Один пользователь — владелец; от всех
остальных полное молчание. Работает круглосуточно в бесплатном контейнере fps.ms с
лимитом 128 МБ памяти, который продлевают руками.

Возможности: «Сегодня», «Завтра», «Сейчас», «Неделя» с перелистыванием и экспортом
недели в `.ics`, «Звонки», inline-календарь по дням семестра, утренняя сводка в 07:30,
напоминание о скорой остановке сервера и датные замены занятий поверх стабильного
расписания. Часовой пояс фиксированный UTC+3, без библиотек времени и без tz-базы
хостинга.

## Что где

- **rust/** — весь код бота: `src/` — модули, `tests/` — тесты и снимки поведения,
  `bin/a11-bot` — собранный Linux-бинарник, из которого живёт прод, `tools/` —
  проверки. Подробности в [rust/README.md](rust/README.md).
- **rust/src/schedule.rs** — единственный источник данных: расписание, замены, звонки,
  типы занятий, границы семестра, якорь чередования недель.
- **rust/tools/check_site.py** — сверка с bteu.by: стабильная таблица, таблица учебных
  недель, начитка и график кураторского часа; найденные замены печатает блоком, который
  человек переносит в данные.
- **SPEC.md** — контракт поведения: форматы сообщений, статусы, правила.
- **run.py** — вход на хосте: клонирует репозиторий, если его нет, проверяет бинарник
  самотестом и запускает его.
- **AGENTS.md** — правила работы для кодинг-агентов; **.agents/skills/verify-bot/** —
  скилл всесторонней проверки.

## Сборка и запуск

```powershell
cp .env.example .env    # BOT_TOKEN от @BotFather, MY_TELEGRAM_ID от @userinfobot
cargo build --release --manifest-path rust/Cargo.toml
rust\target\release\a11-bot.exe --selftest 2    # память и хеш видов, без сети
rust\target\release\a11-bot.exe --check-net     # принят ли токен, в чат ничего не идёт
```

Запускать `a11-bot.exe` без флагов под настоящим токеном не стоит: прод ответит
конфликтом 409 на второй polling-процесс. Для локального прогона нужен тест-токен.

## Проверки

```powershell
python -X utf8 rust/tools/check.py                                        # сборка, тесты, паритет, память
python -X utf8 .agents/skills/verify-bot/scripts/verify_bot.py --local     # то же плюс статика и данные
python -X utf8 .agents/skills/verify-bot/scripts/verify_bot.py             # и ещё прод: 409, деплой, панель
python -X utf8 rust/tools/check_site.py                                    # сверка расписания с сайтом
```

Для `check_site.py` нужен `xlrd`, для `check.py` — cargo. Зелёный итог любой проверки
означает `FAIL=0`; строку итога приводят в отчёте, а не пересказывают словами.

## Прод

Пуш в `main` запускает GitHub Actions: `deploy.yml` просит панель перезапустить
контейнер, `rust.yml` собирает статический musl-бинарник, коммитит его в `rust/bin/` и
сам просит перезапуск, а `healthcheck.yml` каждый час проверяет, что бот держит
long polling, и при сбое будит владельца и пробует рестарт. Сервер продлевают руками
раз в сутки — watchdog напоминает за 30 часов и за 6.

Раз в сутки отдельная проверка сверяет расписание с сайтом: если деканат выложил
начитку или кураторский час, она вносит замену в данные, переснимает эталон видов,
прогоняет гейт и коммитит локально — в прод без слова владельца не лезет.

Базы данных, файлов состояния и веб-сервера нет: всё в памяти, поэтому перезапуск
безопасен и теряет только признаки «уже присылали» у сводки и напоминания.
