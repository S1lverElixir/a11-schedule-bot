# Проверка бота расписания

Один прогон скрипта закрывает 90% вопросов; остальное — сетевые проверки с подводными камнями.

## Запуск

```bash
cd "<корень проекта>" && python -X utf8 .agents/skills/verify-bot/scripts/verify_bot.py
```

- Без аргументов: локальные проверки + сетевые (409-тест, живость воркера, вебхук).
- `--local` — только локальные (без сети; когда не нужен прод или сеть недоступна).
- Код выхода 0 — красок нет. Скрипт печатает секции `ЛОКАЛЬНО` и `ПРОД` со строками
  `[OK] / [WARN] / [FAIL]`.

## Что проверяется

**Локально:** фикстуры workers/test/fixtures (7600 видов, 70 вызовов); пересъёмка
эталона `node workers/tools/dump_views.ts` — вывод обязан совпасть с фикстурой
байт-в-байт; `node --test` (паритет фикстур внутри) и `tsc --noEmit`; статические
правила воркера (фильтр владельца в двух обработчиках, страховка chat_id, constant-time
секрет вебхука, эмодзи в строках, отсутствие литералов токена, два слота крона);
данные (шесть официальных дат недель из таблицы bteu.by, полнота SCHEDULE, покрытие
KIND, границы семестра и якорь, датные замены).

**Сайт:** `python -X utf8 tools/check_site.py` — сверка с bteu.by: стабильная таблица,
таблица учебных недель, начитка и график кураторского часа. Замены он только находит
и печатает блоком для SUBSTITUTIONS; в данные их переносит человек и правит регистр
предметов. Проверять раз в сутки и всегда перед «бот показывает не то».

**Сеть:** прод-бот жив, если `getUpdates?timeout=25` даёт HTTP 409 (401 = невалидный
токен); воркер отвечает на GET; вебхук указывает на воркер без свежих ошибок доставки;
меню команд — /start и /help.

## Подводные камни (не «чинить» скрипт, они намеренные)

- **409-тест работает только с timeout≥5.** С `timeout=0/1` Telegram отвечает «OK»
  без конфликта — это ложное «бот мёртв». Скрипт использует 25 — не меняй.
- **workers.dev за Cloudflare режет python-urllib**, а локальный DNS к workers.dev
  качается волнами — запросы только через curl с браузерным User-Agent, лестницей
  (прямой -4 с ретраями → DoH → anycast-IP), как в скрипте.
- **Паритет значит «не изменил», а не «прав»:** эталона вне фикстур в репозитории нет.
  Видовые снимки переснимает dump_views.ts (гейт сверяет их байт-в-байт), снимки
  обработчиков заморожены и правятся только руками вместе с осознанной сменой
  поведения. Первый настоящий огонь утреннего крона тестом не покрыт.
- **getWebhookInfo.last_error_message прилипает** и после восстановления; скрипт
  судит по свежести last_error_date — не по самому факту поля.

## Как интерпретировать и что говорить пользователю

- `FAIL` в ЛОКАЛЬНО — баг в данных или коде: чинить; при осознанной смене поведения
  переснять виды dump_views.ts, прочитать diff, обновить SPEC тем же коммитом,
  запушить, потом перегнать скрипт и проверить 409-тест.
- `FAIL` в ПРОД при зелёной локальной части — деплой ручной (`npx wrangler deploy`
  из workers/), логи воркера в панели Cloudflare. Свежая ошибка доставки в вебхуке —
  смотреть last_error_date, поле прилипает.
- Итог для пользователя: одним абзацем — зелёное/красное, число пар и диапазон
  сегодня, живость прод-бота. Без простыни сырых логов.
